# sshboard — 決定と未決（2026-08-25）

## D1. 製品名は `sshboard`・発見される語は名前の外に置く — 【決定・2026-08-25】

**Why:**

- **`dbboard` と同じ形です。**`db` + `board`、`ssh` + `board`。
  board ブランドは元々「技術名 + board」であり、ブランドと発見性の二者択一ではありません
- SFTP も exec も、**全部 SSH の上**です。統合後の名前としては SSH が正確です
- 世界の開発者が探す語（`mcp sftp client` / `mcp ssh terminal`）は**製品名に入れません。**
  description / topics / README 冒頭 / MCP レジストリ登録に置きます。
  **実際に探される主経路は MCP のレジストリと一覧サイト**で、そこは description で引かれます
- 後から他の「盤」を足すときにブランドが効きます

**How to apply:** PRD §8「発見される語をどこに置くか」の表に従う。リポ作成時に description と topics を必ず埋める。

## D2. Phase 1 は読み取り専用 — 【決定・2026-08-25】

アップロード・上書き・削除・リネーム・移動・パーミッション変更・転送キュー・
サービス再起動・パッケージ操作・承認 UI を Phase 1 に入れない。

**Why:**

- **解こうとしている痛みが 100% 読み取りです。**障害調査・メール設定調査・提案、どれも読むだけ
- 危険がほぼゼロになるので、**稼働中の本番サーバーを初日から対象にできます**
- 実装量が大きく減ります。転送キュー・上書き衝突・削除確認・承認待ちの機構が丸ごと消えます
- `dbboard` が read-only MCP でこの形を先に成立させています

**How to apply:** Phase 1 の MCP ツールに、サーバー側の状態を変えるものを 1 つも作らない。

## D3. AI に任意コマンドを渡さない — 【決定・2026-08-25】

`run_command(cmd: string)` を作らない。用途ごとの読み取りツールと、
許可リスト方式の `run_readonly` だけを出す。

**Why:**

- `run_command` を 1 つ置けば全部できる。**だから危険**。
  破壊的操作を防ぐ手段が「使わない約束」しか残らない
- **約束は手順書であって、ゲートではない。**忘れた瞬間に穴が開き、
  相手はサーバーなので気づくのは壊れた後
- 許可リストなら**危険なコマンドは呼びようがない**。構造で防げる

**How to apply:**

- 引数で任意の文字列をシェルへ渡す MCP ツールを 1 つも作らない
- `run_readonly` の許可リストは既定を最小にし、実際に必要になったものだけ足す
- **GUI（人）の側は制限しない。**制限するのは AI の口だけ

## D4. ファイルと端末を 1 製品にする — 【決定・2026-08-25】

初版は `sftpboard` / `sshboard` の 2 製品として起草したが、**統合に変更した。**

**Why:**

- **用途が両方を同時に要求する。**障害調査はログ（ファイル）＋ プロセス・サービス（コマンド）、
  メール設定調査は設定ファイル（ファイル）＋ `postconf -n`・listen ポート（コマンド）。
  **片方だけでは終わらない**
- **決定打は MCP の登録。**2 製品だと利用者は MCP を 2 つ登録し、接続先リストを 2 か所で保守する。
  **「片方にはホストを足したが、もう片方に足していない」が必ず起きる。**
  Phase 1 が両方とも読み取り専用である以上、接続層を分ける利益が無い
- SSH 1 本の上で `sftp` サブシステムと `exec` を使い分けるだけになり、接続層はほぼ同じ
- インストーラも 1 つで済む

**How to apply:**

- **1 アプリ 2 画面。1 画面にしない。**既定はファイル 2 ペイン、ターミナルはタブ
- 副ユーザー（従来の慣習でないと作業できない担当者）に端末を覚えさせない
- 分離が必要になる証拠が出たときだけ分ける。**今は証拠が無い**

## D5. 共通部品を先に作らない — 【決定・2026-08-25】

`git-qa` との共通配管（操作記録 / 人と AI の識別 / 承認ゲート / イベントバス /
MCP サーバーの殻 / 資格情報 / Tauri の殻）を、先に crate として切り出さない。

**Why:**

- **使う前に抽象化すると、たいてい外す。**2 本目を書いて初めて本当の境界が分かる
- ただし**コピーで済ませると、承認ゲートの不具合を 3 箇所直して 1 箇所忘れる**。
  監査ログの形式が割れて、AI の操作を製品横断で追えなくなる

**How to apply:**

- 本製品は普通に作る。ただし**配管を crate 境界に置いておく**（あとで引き上げられる形）
- 2 本目（`git-qa` 側）を書くときに、**実測で重複した部分だけ**を `boardkit`（仮）へ引き上げる
- 引き上げないまま 2 本目を書き進めない

**Why:**

- SvelteKit は `dbboard` と揃う。**社内に前例がある方を採る**

  自前実装は「だいたい動くが、たまに表示が壊れる」に必ず到達する。そこは本製品の価値ではない

**そこで脱落する。**バイナリを落とせばそのまま MCP が使える形にする。

## D15. MCP は 127.0.0.1 の Streamable HTTP で出す — 【決定・2026-08-26】

MCP のトランスポートを stdio ではなく、**アプリ自身が loopback に bind する
Streamable HTTP** にする。実装は `rmcp` の `transport-streamable-http-server`。

**Why:**

- **stdio の MCP は、クライアントがサーバーを起動する形になる。**
  Tauri の GUI プロセスの stdin/stdout を MCP クライアントへ渡す方法が無いので、
  stdio を選ぶと別プロセスを立てるしかない。それは D8「MCP はアプリ内蔵」と
  Issue 001「別プロセスを立てない」の両方に反する
- アプリ自身が listen すれば、**増えるプロセスは 0 本。**GUI と MCP が
  同じ Operation Engine・同じ 1 本の SSH を共有する形（PRD §4-1）を保てる
- `rmcp` 3.1.4 に該当のトランスポートがあり、自前で書く部分が無い

**How to apply:**

- **`127.0.0.1` にしか bind しない。`0.0.0.0` にしない。**テストで見張る
  （`the_mcp_port_is_bound_to_loopback_only`）
- **この口は認証を持っていない。**loopback でも、同じ端末の別プロセスからは叩ける。
  **Phase 1 で実際にサーバーを触るツールを載せる前に、トークンを必須にすること。**
  Phase 0 の `ping` は何も触らないので今は無害
- ポート番号の扱いは**まだ決めていない。**Phase 0 は 0 を渡して OS に選ばせている。
  Phase 1 で MCP クライアントへ登録する都合上、固定ポートか、
  実際の番号を設定ファイルへ書き出す形が要る。そこは実際に登録して決める

## D16. 帯が受け取るまで、MCP ツールの応答を返さない — 【決定・2026-08-26】

MCP ツールは、操作を帯へ載せ、**画面が受け取りを返してから**応答を返す。
期限内に返らないときは**ツールを失敗させる。**

**Why:**

- 応答を先に返すと、**AI が返答したあとに画面が追いつく**形になる。
  それは「人が見ている」ことにならない（PRD §4-2・Issue 001 の完了条件）
- 「たぶん出ているはず」で進めると、**画面が固まっていることに誰も気づかない。**
  見えないことが最大の危険（PRD §4-1）である以上、ここは best-effort にしない

**How to apply:**

- `Band::record` は配達票（`Delivery`）を返す。`Delivery::wait_acked` で待つ
- 期限切れ（`DeliveryOutcome::TimedOut`）を握り潰さず、ツールを失敗させる
- **画面をまだ開いていない（購読者 0）ときは待たない。**そこは「見えない」ではなく
  「見る人がいない」であり、別の話
- **「受け取った」の線は DOM に入るところまで。描画（`requestAnimationFrame`）を待たない。**
  WKWebView はウィンドウが前面に無いと rAF を止める。この製品は「人はエディタを見ていて、
  AI が裏で動く」使い方が普通なので、描画を待つ作りにすると**背面にした瞬間に
  MCP が全部失敗する。**2026-08-26 に実機で踏んだ

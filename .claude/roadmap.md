## Phase 1 — 読み取り専用 MVP

### 1-A. 人が使う（既定の画面）

- 接続管理（登録・鍵の指定・接続テスト）
- **ファイル 2 ペイン**（ローカル / リモート）・ダウンロード・パス直打ち
- **ターミナルはタブ**。xterm.js・コピー&ペースト・検索
- **人の側は制限しない。**普通の SFTP クライアント / ターミナルとして使える
- **既存クライアントの使い勝手から離れない**（副ユーザー要件）

### 1-B. AI に見せる（MCP・読み取りのみ）

`list_connections` / `list_directory` / `stat` / `read_file` / `search` / `download` /
`disk_usage` / `process_list` / `service_status` / `runtime_versions` /
`read_log` / `network_listen` / `run_readonly`（許可リスト方式）

**任意コマンドの実行口を作らない**（D3）。**書き込みを 1 つも作らない**（D2）。

### 1-C. 見えるようにする

- AI が読んだファイル・打ったコマンドと出力が、**人の画面に流れる**
- 行頭に `[AI]` / `[Human]` が付く。**面が違っても記録は 1 本**
- AI の実行を止められる。止めた後は人が同じセッションで続けられる

**→ Phase 2 へ進む条件: 既存サービスの保守作業を実際にこれで回し、
「サーバー側の状態を教えてください」が出なくなったことを確認すること。
機能が揃ったことではありません。**

## Phase 2 — 書き込みを扱う

- アップロード・上書き・削除・リネーム・移動・パーミッション変更・転送キュー
- サービス再起動・パッケージ操作
- 承認ゲート（観測=自動 / 変更=人の承認 / 危険=禁止）
- 接続ごと・ディレクトリごとの権限レベル
- sudo の扱い（**AI に無制限の sudo を渡さない**方針の具体化）
- 監査ログの永続化

**Phase 1 で危険を持ち込まなかったので、ここで承認の設計に時間を使えます。**

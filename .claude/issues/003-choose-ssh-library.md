## dbboard から分かったこと（2026-08-26 追記）

**`russh` に house 実績があります。**ただし **D6 はまだ決まりません。**理由は下記。

| | |
|---|---|
| 版 | `russh = "0.62"`、`default-features = false`、`features = ["ring", "flate2", "rsa"]` |
| 用途 | SSH ローカルフォワード（ADR-0069）。**本番で動いています** |
| 選定理由の一部 | ADR-0034 の暗号バックエンド制約（`aws-lc-rs` を入れない）。`cargo tree` で確認済み |
| host key | **検証必須。**russh の `check_server_key` は既定で全部拒否する。blind-accept を型で作れない形にしてある |
| 鍵交換 / 暗号の明示設定 | **無い。**russh の既定のまま繋がっている |

### それでも D6 が決まらない理由

**dbboard は SFTP を使っていません。トンネルだけです。**

D6 の判断材料は 2 つで、そのうち片方しか埋まりません。

1. 実機に繋がるか → **russh の既定で繋がっている実績あり**（ただし bastion が古いとは限らない）
2. `sftp` サブシステムの扱いやすさ → **まったく埋まらない**

そして、ここが効きます:

- **`russh` 本体に SFTP クライアントはありません。**別 crate（`russh-sftp`）が要ります
- **`ssh2`（libssh2）は SFTP を内蔵しています**

つまり「russh に実績がある」は、**SFTP を含めた比較の答えにはなっていません。**
002 で実機に繋ぐときに、**両方で `sftp` サブシステムまで通してから**決めてください。

### 追加の完了条件

- [ ] `russh` + `russh-sftp` で、1 本の接続の上で `sftp` と `exec` の両方を通した
- [ ] `ssh2` でも同じことをした
- [ ] `russh` を採る場合、`aws-lc-rs` が入っていないことを `cargo tree` で確認した（ADR-0034 と揃える）

sshboard

Roadmap

sshboard lets a person and an AI agent look at the same server, on the same screen, over one SSH connection. This page says where that stands.

Done

  • One SSH session shared by the window and the agent, for several servers at once
  • Read-only tools for the agent: files, search, disk, processes, services, logs, listening ports
  • Commands a person allow-listed, by id only; state-changing operations that ask on screen every time
  • A shared terminal with a lock and a stop button; files in two panes with a write fence per connection
  • Health checks a person writes and either side runs, with the previous value beside the new one
  • The agent is woken when the person answers a question on screen (Claude Code channels)
  • Auto-update; macOS for Apple Silicon and Intel; Windows x64 and ARM64; eleven languages

Now

  • Using it on real servers and fixing what that use turns up — that is where almost every issue has come from
  • A design pass on the interface, decided by a person, not by the agent

Next

  • Linux builds
  • Confirming ssh-agent on Windows (named pipe / Pageant)
  • Code signing, once its absence actually hurts someone — say so in an issue
  • Deleting and renaming files inside the write fence (asked for; held for the next phase on purpose)

How we know it works, and when to stop

The one success criterion: the agent stops saying "please show me the state of the server". Not downloads, not stars — whether the back-and-forth disappears during real maintenance.

If people keep handing the agent a raw shell instead, because the fence costs more than it protects, that is the signal to rethink the design rather than add features.

What it will not become

  • A tool that runs any command line the agent writes (run_command)
  • A way to run an agent against a server while nobody is watching
  • A place your keys or passphrases get stored
  • A second SSH session you cannot see
  • A way to move you off the server you already have

ロードマップ

sshboard は、人と AI エージェントが同じサーバーを、同じ画面で、1 本の SSH の上で見るための道具です。このページは、それがいまどこまで来ているかを書いています。

済んだこと

  • 窓とエージェントが 1 本の SSH を共有する（何台でも同時に）
  • エージェント向けの読み取りの道具：ファイル・検索・空き容量・プロセス・サービス・ログ・待ち受け
  • 人が許したコマンドを id だけで走らせる。状態を変える操作は、毎回画面で尋ねる
  • 錠と停止ボタン付きの共有端末。接続ごとに書き込みの囲いを持つ 2 ペインのファイル画面
  • 人が書く点検表を、人も AI も回せる（前回の値を隣に並べる）
  • 人が画面で答えたら、待っている AI を起こす（Claude Code の channels）
  • 自動更新。macOS は Apple シリコンと Intel、Windows は x64 と ARM64。11 言語

いま

  • 実際のサーバーで使い、出てきたものを直す —— ほとんどの Issue はここから来ています
  • 画面の見た目を整える（決めるのは人で、エージェントではありません）

次

  • Linux 版
  • Windows の ssh-agent（名前付きパイプ・Pageant）の確認
  • コード署名 —— 無いことで実際に困った人が出たら。Issue で言ってください
  • 書き込みの囲いの中での削除・名前変更（要望あり。次の段に、意図して置いています）

うまくいっているかの物差しと、止めどころ

成功条件は 1 つだけです：エージェントが「サーバーの状態を見せてください」と言わなくなること。ダウンロード数でも星の数でもなく、実際の保守作業で往復が消えたかどうかです。

囲いが守るものより手間の方が大きく、結局エージェントに素のシェルを渡す人が続くなら、それは機能を足す合図ではなく、作りを考え直す合図です。

作らないもの

  • エージェントが書いた任意のコマンド行を走らせる口（run_command）
  • 誰も見ていない所でエージェントにサーバーを触らせる道
  • 鍵やパスフレーズをしまう場所
  • あなたから見えない 2 本目の SSH
  • いまのサーバーから別の基盤へ移させる道具
